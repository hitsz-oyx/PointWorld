### 1. `export_clip.py` 当前调用方式和 import 冲突


我建议就这么改，不需要做 `sys.path` hack。

### 2. depth 目前是错的，而且首先会有 shape 问题

你现在：

```python
depth = np.asarray(obs[f"{cam}_depth"], dtype=np.float32)
```

直接保存。

后面：

```python
H, W = depth_per_t[0].shape
```

但 LIBERO 固定依赖 `robosuite==1.4.0`。

robosuite 1.4 的 camera observable 明确把 depth 扩成：

```python
np.expand_dims(depth[::convention], axis=-1)
```

也就是：

[
(H,W,1)
]

而不是：

[
(H,W)
]

所以这里：

```python
H, W = depth.shape
```

首先就可能报：

```text
ValueError: too many values to unpack
```

更关键的是，MuJoCo 默认 depth 是归一化到 ([0,1]) 的 depth buffer，robosuite 官方提供 `get_real_depth_map` 转为真实距离。

你现在直接：

```python
z_cam = depth
```

实际上是把 normalized depth 当成米。

应该直接：

```python
from robosuite.utils import camera_utils

depth = np.asarray(
    obs[f"{cam}_depth"],
    dtype=np.float32,
).squeeze(-1)

depth = camera_utils.get_real_depth_map(
    env.sim,
    depth,
).astype(np.float32)
```

**这个必须修。**

否则：

[
P_{\text{scene}}
]

尺度就是错的，而 PointWorld scene encoder 会直接比较 projected (z) 和 depth image。

### 3. 目前 camera extrinsic 正好反了

这是目前最严重的 convention bug。

你定义：

```python
def get_camera_extrinsic(...):
    ...
    T[:3, :3] = xmat
    T[:3, 3] = xpos
    return T
```

并且注释说它是：

```text
world-from-camera
```

即：

[
{}^WT_C
]

然后保存：

```python
"extrinsic": T_w_c
```

但是 PointWorld 中：

```python
world2cam = extr.float()
pts_cam = world2cam @ pts_world
```

它明确把 `extrinsic` 当：

[
{}^CT_W
]

也就是 **world-to-camera**。

所以现在是：

[
\boxed{
\text{PointWorld expects }{}^CT_W
}
]

你却给了：

[
\boxed{
{}^WT_C
}
]

应该：

```python
T_w_c = ...
T_c_w = np.linalg.inv(T_w_c)

payload["extrinsic"] = T_c_w.astype(np.float32)
```

### 4. 而且你的 camera frame 还缺 MuJoCo→OpenCV axis correction

现在直接使用：

```python
cam_xmat
```

作为 camera rotation。

但 robosuite 1.4 官方代码明确指出 MuJoCo camera axis convention 需要修正，并右乘：

[
T_{\text{corr}}
===============

\operatorname{diag}(1,-1,-1,1)
]

所以我建议**不要自己重写 camera geometry**。

直接用：

```python
from robosuite.utils import camera_utils

K = camera_utils.get_camera_intrinsic_matrix(
    env.sim,
    camera_name,
    H,
    W,
)

T_w_c = camera_utils.get_camera_extrinsic_matrix(
    env.sim,
    camera_name,
)

T_c_w = np.linalg.inv(T_w_c)
```

然后：

```python
points_world = backproject_depth(
    depth,
    K,
    T_w_c,
)

payload["extrinsic"] = T_c_w.astype(np.float32)
```

而且你当前 intrinsic 用：

```python
cx = 0.5 * (width - 1)
cy = 0.5 * (height - 1)
```

robosuite 官方是：

```python
camera_width / 2
camera_height / 2
```

直接复用官方函数，少制造一个 0.5 pixel convention mismatch。

## 你的 reprojection test 为什么没发现 extrinsic 错？

因为 test 和 exporter 使用了**同一套反向约定**。

test 读取：

```python
T_w_c = sample["extrinsic_per_cam"]["camera_0"]
```

然后主动：

```python
T_c_w = np.linalg.inv(T_w_c)
```

再投影。

因此 test 验证的是：

> 你自己的 `backproject_depth` 与自己的 inverse convention 自洽。

但没有验证：

> PointWorld 会不会正确解释 `extrinsic`。

实际上 PointWorld **不会 inverse**，它直接：

```python
world2cam = extr
```

所以这个测试现在反而把错误 convention 固化了。

正确测试应该直接：

```python
E = sample["extrinsic_per_cam"]["camera_0"]

pts_cam = (
    E[:3, :3] @ pts.T
    + E[:3, 3:4]
).T
```

**不取逆。**

```text
instance
```

其中 `element` 是 **per-geom segmentation**。

```python
seg = obs[f"{cam}_segmentation_element"].squeeze(-1)
```

## 8. robot point flow 目前只能叫 placeholder，不能拿来做正式 zero-shot 结论

你现在明确写了：

```python
sample_robot_points_around_body
```

然后在 EEF 周围随机采一个球。

问题是 Panda gripper XML 中真正的 hand mesh 位于 `right_gripper` body，两个 finger mesh 分别位于 `leftfinger` 和 `rightfinger`；`eef` body 自己只有 sites，没有 gripper visual mesh。

也就是说，你当前：

```text
PointWorld training:
actual gripper mesh point flow

你的 LIBERO:
random spherical cloud around EEF
```

OOD 非常严重。

更关键的是：

```text
left finger
right finger
```

opening / closing 的 geometry motion 完全没进入 `robot_flows`。

虽然你另给了：

```python
right_gripper_open
```

但 PointWorld 的 action representation 核心仍是 robot point flow。

正式版本应该：

```text
PandaGripper
├── hand geom/mesh
├── leftfinger geom/mesh
└── rightfinger geom/mesh
```

对三个 rigid body 各自：

[
p_{\text{local}}
================

(T^W_{B,0})^{-1}p_W
]

然后：

[
p_W^t=T^W_{B,t}p_{\text{local}}
]

这样 gripper 开合本身就自然体现在 robot point trajectory 中。

### 9. `robot_normals` 没有随机器人旋转

```python
robot_normals = ...
robot_normals = np.broadcast_to(
    robot_normals,
    (T_FRAMES, ...)

```

也就是：

[

[

## P1：evaluation script 有一个确定的 runtime bug

这里：

```python
err = ...
moved_mask = ...  # (B, N)

err_masked = err[:, moved_mask]
```

shape 是：

```text
err        (B, 10, N)
moved_mask (B, N)
```

这个 Boolean indexing 写法不对，会报 shape mismatch。

改成：

```python
mask = moved_mask[:, None, :].expand_as(err)
err_masked = err[mask]
```

完整：

```python
err = torch.linalg.norm(
    pred_scene_flows[:, 1:] - gt_scene_flows[:, 1:],
    dim=-1,
)

gt_movement = torch.linalg.norm(
    gt_scene_flows[:, 1:] - gt_scene_flows[:, :1],
    dim=-1,
)

moved_mask = gt_movement.max(dim=1).values > 0.005

epe_all = err.mean().item()

expanded_moved_mask = moved_mask[:, None, :].expand_as(err)
moved_err = err[expanded_moved_mask]

epe_moved = (
    moved_err.mean().item()
    if moved_err.numel() > 0
    else float("nan")
)
```

这个现在没有 test 覆盖。

## 10. 你当前的 `epe_moved` 和 PointWorld 官方 moved metric 不是同一个定义

你的定义是：

[
\max_t|p_i^t-p_i^0|>5\text{ mm}
]

PointWorld pipeline 则先计算：

[
\Delta p_t=p_t-p_{t-1}
]

然后根据每步 movement magnitude 生成 soft selector，再以 (0.5) threshold 定义 moved mask。

所以你的指标可以保留，但建议命名：

```text
epe_ever_moved_m
```

不要叫：

```text
l2_moved
```

否则以后和官方 metric 对比会混淆。

## 11. 当前 `mean_confidence` 没有意义

你默认：

```python
--model_domain behavior
```

然后输出：

```python
outputs["confidence"].mean()
```

但是 PointWorld 对 domain 中包含 `"behavior"` 的 sample，会把 log variance 替换成 simulation constant：

```python
SIM_DOMAIN_KEYWORDS = ["behavior"]
...
const_val = log(SIM_VAR_CONST)
...
log_var = torch.where(sim_mask, const_tensor, log_var)
```

所以这里的：

```text
mean_confidence
```

不是 PointWorld 对 LIBERO 的 learned uncertainty。

建议第一版直接删掉。
