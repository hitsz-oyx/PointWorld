能看到。**从你现在的 `viser` 可视化代码看，“像有两个桌子”非常有可能是真的两路相机点云没有对齐，而不是 Viser 渲染问题。**

## 直接原因：你把两个相机的点云直接拼起来了

当前代码：

```python
flows_c0 = _cam(0, "scene_flows")
flows_c1 = _cam(1, "scene_flows")

    [flows_c0, flows_c1],
```

也就是：

[

]

没有 registration、voxel fusion 或 cross-camera dedup。

因此同一张桌子本身确实会被两个 camera 各采一次。

但这里有个关键判断：

> **如果两路 camera→world 几何完全正确，两张桌子应该空间重合，只是点更密。**

如果你看到的是这种：

```text

       table B
```

即明显错开，那么问题不是“没有去重”，而是：

[
P_{\text{cam0}}^w
\neq
P_{\text{cam1}}^w
]

说明至少一路 camera backprojection 的世界坐标错了。

# 我现在最怀疑的是 image convention

你当前 backprojection 明确使用 **OpenCV convention**：

```python
x_cam = (u - cx) * depth / fx
y_cam = (v - cy) * depth / fy
z_cam = depth
```

并且 camera extrinsic 使用 robosuite 的 OpenCV-axis-corrected camera pose。

但是 robosuite 1.4 默认：

```python
IMAGE_CONVENTION = "opengl"
```

它的 camera observable 在创建时根据：

```python
IMAGE_CONVENTION_MAPPING = {
    "opengl": 1,
    "opencv": -1,
}
```

决定是否竖直翻转图像。

camera sensor 实际执行：

```python
convention = IMAGE_CONVENTION_MAPPING[
    macros.IMAGE_CONVENTION
]

...

return rgb[::convention]
```

depth 和 segmentation 使用相同 image convention。

但你的 exporter **没有设置 `macros.IMAGE_CONVENTION`**。当前 import 区只有 LIBERO 相关模块，没有 robosuite macros 配置。

LIBERO 官方 `init_path.py` 甚至有：

```python
# import robosuite.utils.macros as macros
# macros.IMAGE_CONVENTION = "opencv"
```

但这两行被注释掉了。

所以现在很可能是：

```text
depth / RGB / seg
    = OpenGL image orientation

K + T_c_w + backprojection
    = OpenCV camera convention
```

这两套 convention 混用了。

## 为什么会看成两个桌子？

假设正确像素是：

[
(u,v)
]

OpenGL/OpenCV 的竖直方向不一致时，你实际可能用：

[
(u,H-1-v)
]

对应深度值，却按照：

[
y_c=\frac{v-c_y}{f_y}z
]

进行反投影。

因此：

[
p_c=
\begin{bmatrix}
x_c\
y_c\
z_c
\end{bmatrix}
]

中的 (y_c) 错了。

再分别使用：

[
T^W_{C_0}
]

和：

[
T^W_{C_1}
]

变换到世界系：

[
p_w^{(0)}=T^W_{C_0}p_c^{(0)}
]

[
p_w^{(1)}=T^W_{C_1}p_c^{(1)}
]

由于两个 camera 姿态不同，**同一个 image-y 错误经过不同旋转后会变成不同方向的 world-space 偏差**。

结果就是：

```text
agentview 桌子
        \
         \  错位

eye-in-hand 桌子
```

这和你说的“感觉有两个桌子”非常吻合。

## 还有一个可视化代码的小坑

你的 `_cam`：

```python
if key in clip:
    return clip[key]

if f"camera_0_{name}" in clip:
    return clip[f"camera_0_{name}"]
```

所以假设 `camera_1_*` 不存在：

```python
flows_c1 = _cam(1, "scene_flows")
```

实际上会返回：

```python
camera_0_scene_flows
```

然后：

```python
np.concatenate([
    camera_0,
    camera_0,
])
```

即**真的把同一张桌子复制两遍**。

虽然理论上完全重合，但这个 fallback 对 debug 很不友好。

我建议改成：

```python
def _cam(cam_idx: int, name: str) -> np.ndarray:
    key = f"camera_{cam_idx}_{name}"

    if key not in clip:
        raise KeyError(
            f"Missing camera payload: {key}"
        )

    return clip[key]
```
