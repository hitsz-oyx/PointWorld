可以用 Hugging Face 上的 **`small-droid/model-best.pt`** 作为初始化权重，再在 LIBERO 上微调。官方仓库确实提供了这个 small checkpoint，文件约 1.83 GB。([Hugging Face][1])

但你当前分支**还不能直接用一条 `train.py --model_path ...` 命令完成微调**。需要先补三个环节：

[
\boxed{
\text{LIBERO训练数据读取}
+
\text{LIBERO归一化统计}
+
\text{仅加载模型权重的微调模式}
}
]

# 一、为什么不能直接使用 `--model_path`

不能直接这样运行：

```bash
python train.py \
  --model_path pretrained_checkpoints/small-droid/model-best.pt \
  --domains libero
```

因为你当前的 `--model_path` 表示的是**恢复训练**，不是“从预训练权重开始一次新训练”。它会同时恢复：

* 模型参数；
* 优化器状态；
* `sample_count`；
* `batch_count`；
* `best_loss`；
* checkpoint 中保存的 domain 和模型配置。

small checkpoint 的数据域是：

```text
droid
```

checkpoint contract 又会把保存的 `domains=droid` 和 DROID 的归一化设置重新写入当前参数。

因此应当新增：

```bash
--finetune_from
```

其含义是：

```text
只加载预训练模型权重
不加载优化器
不恢复训练步数
不继承 DROID 归一化统计
重新建立 LIBERO 训练状态
```


# 三、准备 LIBERO 训练数据

你当前已经有：

```text
tools/libero/export_trajectory_windows.py
```

它可以把一条 LIBERO demo 导出为多个：

```text
1 context frame + 10 future frames
```

的 11 帧 `.npz` 窗口。

现有数据结构已经包含：

* 场景点的 11 帧 GT 轨迹；
* RGB、Depth；
* 相机内外参；
* 机器人点轨迹；
* 机器人特征；
* 有效点和监督 mask。

## 数据集划分方式

必须先按完整 demo 划分：

```text
train trajectories
val trajectories
test trajectories
```

再从每组轨迹导出窗口。

不要把同一条轨迹导出的重叠窗口随机分到训练集和验证集，例如：

```text
demo_001 window 0-10  -> train
demo_001 window 1-11  -> val
```

这样会产生严重数据泄漏。

建议目录：

```text
data/libero_pointworld/
├── train/
│   ├── trajectory_000/
│   ├── trajectory_001/
│   └── split.json
├── val/
│   ├── trajectory_100/
│   └── split.json
└── test/
    └── ...
```

训练集可以使用：

```text
stride = 1 或 2
```

验证和测试使用：

```text
stride = 10
```

这样训练样本较多，同时验证窗口之间尽量减少重复。

# 四、增加 LIBERO Dataset

当前 `train.py` 的数据管线只读取 WebDataset `.tar`，并且 decoder 只支持：

```text
droid
behavior
```

遇到 `libero` 会直接失败。

你的 LIBERO 数据已经是 `.npz`，所以最小改动不是把它强行转成 DROID 格式，而是新增：

```text
dataset_components/libero_dataset.py
```

基本逻辑：

```python
from pathlib import Path

import numpy as np
from torch.utils.data import Dataset

from tools.libero.sample_schema import flatten_for_pointworld


class LiberoNPZDataset(Dataset):
    def __init__(self, root: str, transform):
        self.root = Path(root)
        self.files = sorted(self.root.rglob("*.npz"))
        self.transform = transform

        if not self.files:
            raise RuntimeError(f"No LIBERO npz files found under {self.root}")

    def __len__(self) -> int:
        return len(self.files)

    def __getitem__(self, index: int):
        path = self.files[index]

        with np.load(path, allow_pickle=True) as data:
            sample = {key: data[key] for key in data.files}

        sample = flatten_for_pointworld(sample)
        sample["__domain__"] = "libero"
        sample["__key__"] = path.stem

        sample = self.transform(sample)
        return sample
```

不过这里的 `transform` 不能自己随便写，需要直接复用现有 LIBERO 评估脚本中的处理流程：

```text
load npz
→ flatten_for_pointworld
→ 固定选择相机
→ canonicalize gripper fields
→ PointWorld release pipeline
→ collate
```

你的 `eval_libero_clip.py` 已经实现了这条单样本处理链，可以把共同部分提取为可复用函数。

然后在：

```text
dataset_components/dataloader.py
```

中增加：

```python
if args.dataset_format == "libero_npz":
    train_dataset = LiberoNPZDataset(
        args.data_dir_train,
        transform=train_transform,
    )
    test_dataset = LiberoNPZDataset(
        args.data_dir_test,
        transform=test_transform,
    )
```

并在 `arguments.py` 中增加：

```python
parser.add_argument(
    "--dataset_format",
    type=str,
    default="webdataset",
    choices=["webdataset", "libero_npz"],
)
```

# 五、必须计算 LIBERO 自己的归一化统计

不能继续使用：

```text
stats/droid
```

也不建议把 LIBERO 临时伪装为：

```text
behavior
```

现有评估脚本中的 `behavior` alias 只是为了使用发布模型进行 smoke test，也就是验证流程是否能跑通，并不是真正对齐的数据归一化。

新增：

```text
tools/libero/compute_norm_stats.py
```

输出：

```text
stats/libero/norm_stats.json
```

PointWorld 要求统计文件至少包含：

```json
{
  "statistics": {
    "libero": {
      "robot_features": {
        "mean": [],
        "variance": []
      },
      "scene_features": {
        "mean": [],
        "variance": []
      }
    }
  },
  "per_timestep_statistics": {
    "libero": {
      "gt_scene_flows_relative": {
        "timestep_0": {
          "mean": [0, 0, 0],
          "variance": [0, 0, 0]
        },
        "timestep_1": {},
        "timestep_2": {},
        "...": {},
        "timestep_10": {}
      }
    }
  }
}
```

仓库加载统计量时，会对每个 domain、每个时间步读取：

* `gt_scene_flows_relative` 的均值和方差；
* `robot_features` 的均值和方差；
* `scene_features` 的均值和方差。

目标场景流定义为：

```python
relative_flow = scene_flows - scene_flows[0:1]
```

即：

[
\Delta \mathbf p_{t,i}
======================

\mathbf p_{t,i}-\mathbf p_{0,i}
]

统计时只使用：

```python
valid_mask = scene_exists & scene_supervised_mask
```

而且只能使用**训练集轨迹**计算，不能混入 val/test。

代码内部最终使用的是：

[
\frac{x-\mu}{\sqrt{\mathrm{variance}}}
]

也就是除以标准差，而不是直接除以方差。

# 六、新增真正的 `--finetune_from`

在 `arguments.py` 中增加：

```python
parser.add_argument(
    "--finetune_from",
    type=str,
    default="",
    help="Initialize model weights from a checkpoint without restoring optimizer or counters.",
)
```

然后不要让它进入现有的：

```python
load_model_config_from_checkpoint(...)
load_checkpoint(...)
```

恢复训练路径。

## 1. 从 checkpoint 继承结构参数

应继承：

```text
ptv3_size
ptv3_patch_size
predictor_dim
max_scene_points
max_robot_points
grid_size
depth_threshold
```

不应继承：

```text
domains
norm_stats_path
data_dir_train
data_dir_test
optimizer state
sample_count
batch_count
best_loss
```

## 2. 跳过 DROID 归一化 buffer

这些参数并不是学习权重，而是数据集统计量：

```python
NORM_BUFFER_NAMES = {
    "norm_stats_per_step_mean",
    "norm_stats_per_step_var",
    "robot_norm_mean",
    "robot_norm_var",
    "scene_norm_mean",
    "scene_norm_var",
}
```

可以增加一个加载函数：

```python
from pathlib import Path

import torch


NORM_BUFFER_NAMES = {
    "norm_stats_per_step_mean",
    "norm_stats_per_step_var",
    "robot_norm_mean",
    "robot_norm_var",
    "scene_norm_mean",
    "scene_norm_var",
}


def load_finetune_weights(model, checkpoint_path: str) -> None:
    checkpoint_path = Path(checkpoint_path)
    if not checkpoint_path.is_file():
        raise FileNotFoundError(checkpoint_path)

    checkpoint = torch.load(
        checkpoint_path,
        map_location="cpu",
        weights_only=False,
    )

    state_dict = checkpoint["model_state_dict"]

    cleaned_state_dict = {}
    for key, value in state_dict.items():
        if key.startswith("module."):
            key = key[len("module."):]

        if any(key.endswith(name) for name in NORM_BUFFER_NAMES):
            continue

        cleaned_state_dict[key] = value

    result = model.load_state_dict(cleaned_state_dict, strict=False)

    unexpected = set(result.unexpected_keys)
    missing = set(result.missing_keys)

    allowed_missing = {
        key
        for key in model.state_dict()
        if any(key.endswith(name) for name in NORM_BUFFER_NAMES)
    }

    if unexpected:
        raise RuntimeError(
            f"Unexpected checkpoint keys: {sorted(unexpected)}"
        )

    invalid_missing = missing - allowed_missing
    if invalid_missing:
        raise RuntimeError(
            f"Unexpected missing model keys: {sorted(invalid_missing)}"
        )
```

模型建立时使用：

```text
domains = ["libero"]
norm_stats_path = "stats/libero"
```

这样归一化 buffer 会从 LIBERO stats 初始化，其余网络参数从 small-droid 初始化。

# 七、建议的第一版微调命令

完成上述修改后，先单卡运行：

```bash
CUDA_VISIBLE_DEVICES=0 python train.py \
  --exp_name pw_small_libero_ft \
  --seed 42 \
  --device cuda \
  --dataset_format libero_npz \
  --finetune_from pretrained_checkpoints/small-droid/model-best.pt \
  --data_dir_train /path/to/libero_pointworld/train \
  --data_dir_test /path/to/libero_pointworld/val \
  --domains libero \
  --norm_stats_path stats/libero \
  --model PointWorld \
  --batch_size 2 \
  --num_epochs 15 \
  --lr 3e-5 \
  --weight_decay 1e-4 \
  --max_scene_points 10000 \
  --max_robot_points 1000 \
  --robot_features "robot_flows,robot_colors,robot_normals,gripper_open,robot_velocity,robot_acceleration" \
  --scene_features "scene_flows,scene_colors,scene_normals,gripper_open,dist2robot" \
  --loss heteroscedastic_trajectory_l2 \
  --mixing_mode mix_by_sample \
  --train_min_num_cameras 2 \
  --train_max_num_cameras 2 \
  --eval_min_num_cameras 2 \
  --eval_max_num_cameras 2 \
  --test_every_n_steps 500 \
  --save_every_n_steps 500 \
  --disable_compile
```

这里的：

```text
lr = 3e-5
```

是微调建议起点，不是官方从头训练参数。官方从头训练 small 模型使用的量级可以达到 (10^{-3})，但对 LIBERO 小数据集直接使用通常过大。官方代码提供的是从头训练流程，没有提供现成的 LIBERO 微调配置。([GitHub][2])

显存不够时先改为：

```bash
--batch_size 1
```

显存充足时可以尝试：

```bash
--batch_size 4
```

# 八、相机设置要固定

为了最终给论文做公平比较，建议训练和评估都固定使用：

```text
birdview
sideview
```

并固定：

```bash
--train_min_num_cameras 2
--train_max_num_cameras 2
--eval_min_num_cameras 2
--eval_max_num_cameras 2
```

不要训练时随机选 1～3 个相机，而测试时固定两个，否则零样本模型、微调模型和 ORD-WM 的输入条件可能不一致。

具体相机名称应在 LIBERO Dataset 中显式选择，而不只是设置数量。

# 九、建议按三个阶段运行

## 阶段 1：数据管线自检

只使用 5～10 条轨迹：

```text
约 100～500 个窗口
```

目标：

* 所有张量没有 NaN；
* `scene_flows` 是米；
* 第 0 帧 relative flow 接近 0；
* loss 能下降；
* 模型能过拟合一个极小训练集。

## 阶段 2：零样本基线

用原始 small-droid 在固定测试集上计算：

```text
EPE@1
EPE@10
CD@1
CD@10
```

作为：

```text
PointWorld-small zero-shot
```

## 阶段 3：LIBERO 微调

使用完全相同的：

* 测试轨迹；
* 相机；
* 点云处理；
* 点数；
* CD 定义；

得到：

```text
PointWorld-small fine-tuned on LIBERO
```

最终表格可以写成：

| Method           | Training          | Norm. L1@1 ↓ | CD@1 ↓ | Norm. L1@10 ↓ | CD@10 ↓ |
| ---------------- | ----------------- | -----------: | -----: | ------------: | ------: |
| PointWorld-small | DROID, zero-shot  |              |        |               |         |
| PointWorld-small | DROID → LIBERO FT |              |        |               |         |
| ORD-WM           | LIBERO            |              |        |               |         |

最先需要修改的是：

```text
dataset_components/libero_dataset.py
tools/libero/compute_norm_stats.py
arguments.py
training/checkpointing.py
training/trainer.py
dataset_components/dataloader.py
```

你当前分支已有 LIBERO 推理所需的大部分数据转换逻辑，主要工作不是重新构造数据，而是把这套单样本评估处理抽成可训练的 Dataset，并增加干净的 weights-only 微调入口。
