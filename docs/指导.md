## P0-1：`backproject_depth` 的公式错了

当前：

```python
R = T_c_w[:3, :3]
t = T_c_w[:3, 3]

pts_world = pts_cam @ R.T - (R.T @ t)
```

但定义是：

[
p_c=Rp_w+t
]

因此：

[
p_w=R^\top(p_c-t)
]

对于代码中的 row-vector：

```python
pts_world = (pts_cam - t[None, :]) @ R
```

而不是：

```python
pts_cam @ R.T - R.T @ t
```

robosuite 的 camera extrinsic 是 camera pose (T^W_C)，world-to-camera 应由其 inverse 得到。官方 camera projection 同样明确使用 camera pose 的 inverse 做 world→camera。

最保险的实现不要手推：

```python
T_w_c = np.linalg.inv(T_c_w)

ones = np.ones((pts_cam.shape[0], 1), dtype=np.float32)
pts_cam_h = np.concatenate([pts_cam, ones], axis=-1)

pts_world = (
    T_w_c @ pts_cam_h.T
).T[:, :3]
```

### 为什么测试没发现？

因为 synthetic test 使用：

```python
T_c_w = np.eye(4)
```

当：

[
R=I,\quad t=0
]

正确公式和错误公式完全一样。

**必须增加 non-identity camera test。**

例如：

```python
R = rotation_y(0.4) @ rotation_x(-0.2)
t = np.array([0.3, -0.1, 0.7])
```

然后检查：

```python
pts_world = backproject_depth(...)
pts_cam_reproj = (
    T_c_w[:3, :3] @ pts_world.reshape(-1, 3).T
    + T_c_w[:3, 3:4]
).T

assert np.allclose(
    pts_cam_reproj[:, 2],
    depth.reshape(-1),
)
```

这是当前**优先级最高的问题**。

## P0-2：element segmentation 仍然错一位

当前代码：

```python
seg = seg_map.squeeze(-1).astype(np.int32)

safe = np.clip(seg - 1, -1, ngeom - 1)

body_id = np.where(
    seg > 0,
    env.sim.model.geom_bodyid[safe] + 1,
    0,
)
```

并明确认为：

```text
element segmentation = geom id + 1
```

但 robosuite 1.4 官方实现不是这样。

对于：

```python
cam_s == "element"
```

代码是：

```python
mapping = None
```

然后直接：

```python
seg = self.sim.render(..., segmentation=True)
seg = seg[..., 1]

if mapping is not None:
    ...
    + 1
```

也就是说 **`+1` 仅发生在 instance/class mapping**；element 直接返回 raw geom ID。

所以应该：

```python
seg = seg_map.squeeze(-1).astype(np.int32)

valid_geom = (
    (seg >= 0)
    & (seg < env.sim.model.ngeom)
)

body_id = np.full(
    seg.shape,
    -1,
    dtype=np.int32,
)

body_id[valid_geom] = env.sim.model.geom_bodyid[
    seg[valid_geom]
]
```

不能：

```python
seg - 1
```

当前结果是：

```text
geom 0  -> background
geom 1  -> 查询 geom 0
geom 2  -> 查询 geom 1
...
```

因此所有 scene point ownership 都整体错位。

这会直接污染：

[
p_i^t=T_{b,t}T_{b,0}^{-1}p_i^0
]

因为 (b) 选错了。

## P0-3：frame 0 observation 仍可能是 stale，而且后面又混入 frame 10 camera

这里实际上有两个问题。

### 第一层：直接 set state 后没有 force-update observable

当前：

```python
env.sim.set_state_from_flattened(
    states[args.start_idx]
)
env.sim.forward()

per_cam0, gpose0, gopen0 = capture_frame(...)
```

`capture_frame` 内：

```python
obs = _get_obs(env)
```

而 `_get_obs` 最后调用：

```python
obj._get_observations()
```

没有：

```python
force_update=True
```

robosuite 官方明确说明：**直接修改 simulation state 后，需要 force-update observables**。`_get_observations(force_update=False)` 默认只是读取 observable 当前缓存。

LIBERO 自己已经提供：

```python
def regenerate_obs_from_state(self, mujoco_state):
    self.set_state(mujoco_state)
    self.env.sim.forward()
    self.check_success()
    self._post_process()
    self._update_observables(force=True)
    return self.env._get_observations()
```

所以直接：

```python
obs0 = env.regenerate_obs_from_state(
    states[args.start_idx]
)
```

更合理。

### 第二层：`build_scene_trajectory` 仍从 frame 10 env 读取 camera

你 replay 完十步：

```python
for k in range(T_FRAMES - 1):
    env.step(action)
```

此时：

[
env=s_{t+10}
]

然后：

```python
payload = build_scene_trajectory(
    env,
    ...
)
```

`build_scene_trajectory` 内又读取：

```python
K = get_camera_intrinsic(env, camera_name, H, W)
T_c_w = get_camera_extrinsic_c_w(env, camera_name)
T_w_c = get_camera_extrinsic_w_c(env, camera_name)

rgb0 = _get_obs(env)[f"{camera_name}_image"]
```

所以现在实际有可能是：

[
\text{depth}=D_t
]

但：

[
RGB=RGB_{t+10}
]

以及 eye-in-hand：

[
T^C_W=T^{C_{t+10}}_W
]

这个问题还没有修。

甚至代码已经保存了：

```python
rgb0_per_cam
```

但是后面完全没用。

### 正确结构

frame 0 立刻缓存：

```python
camera_t0 = {}

for cam in args.camera_names:
    rgb0, depth0, seg0 = per_cam0[cam]

    camera_t0[cam] = {
        "rgb": rgb0.copy(),
        "depth": depth0.copy(),
        "seg": seg0.copy(),
        "K": get_camera_intrinsic(
            env, cam,
            args.camera_height,
            args.camera_width,
        ),
        "T_c_w": get_camera_extrinsic_c_w(env, cam),
        "T_w_c": get_camera_extrinsic_w_c(env, cam),
    }
```

然后：

```python
build_scene_trajectory(
    depth_per_t=...,
    body_name_t0=...,
    camera_t0=camera_t0[cam],
    ...
)
```

`build_scene_trajectory` **不要再读 env camera state**。

## P0-4：单 clip eval 没有 `model.eval()`

当前：

```python
trainer = Trainer(
    args,
    inference_only=True,
    data_info_dict=None,

...
```

但是：

```python

```

只是 `BaseModel.forward` 的普通参数。

它不会执行：

```python

```

PointWorld 的 PTV3 配置：


```python
drop_path=PTV3_DROP_PATH
```

```python
self.model.eval()
```

然后才：

```python
outputs = self.model(
    batch,
```

```python
trainer = Trainer(
    args,

    data_info_dict=None,

trainer.model.eval()

with torch.inference_mode():
    outputs = trainer.model(
        batch,
        training=False,
```

这个也是确定 bug。

# P1-2：robot point 虽然不再是球，但仍不是真正 surface sampling

现在 primitive：

```python
if box:
    pts = rng.uniform(-hs, hs, size=(16, 3))
```

这是在 box **体积内部**均匀采样。

cylinder：

```python
rr = r * sqrt(uniform(...))
z = uniform(-h, h)
```

同样是在 cylinder **体积内部**采样。

PointWorld 官方 RobotSampler 做的是：

```python
deterministic_sample_surface
```

按 mesh face area 采 triangle，然后使用对应：

```python
mesh.face_normals
```

你当前 robot normals 则是：

```python
normals_local = local_points - body_origin
normals_local /= norm(...)
```

也就是“从 body origin 径向朝外”。

对于 box：

[
n_{\text{true}}\in
{
\pm e_x,\pm e_y,\pm e_z
}
]

而你的 normal：

[
n=\frac{p}{|p|}
]

显然不是 surface normal。

而 PointWorld 的 robot features 确实包含：

```text
robot_normals
```

因此这会造成 robot conditioning distribution mismatch。

**跑通 forward 可以接受，解释 zero-shot EPE 前最好修。**

# P1-3：`robot0_link6` 加进 gripper cloud 很可疑

现在显式：

```python
if name in (
    "robot0_link6",
    "robot0_link7",
```

我理解你是根据真实 LIBERO model inspection，发现 hand visual geoms 最终挂在 link7。

`link7` 可以有合理性。


已经明显更接近 wrist / arm。

PointWorld release 的 RobotSampler 是：


其语义明确是仅保留 gripper-related meshes。

```text

gripper-only action geometry
```

还是 OOD。

```text
PandaGripper visual/contact geoms
        ↓
geom id
        ↓
geom_bodyid
        ↓
需要跟踪的 body
```
